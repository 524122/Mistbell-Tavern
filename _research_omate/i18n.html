# OMate Global4 分支国际化规范文档

# 概述

本文档基于 global 分支的国际化实现经验，为 gloabal4 分支制定完整的国际化（i18n）实施规范。目标是实现多语言支持，提升用户体验，使应用能够服务于不同语言背景的用户。

# 当前状态分析

# gloabal4 分支现状

  • ✅ 已有基础国际化框架（AppLocalizations 类）
  • ✅ main.dart 中已配置国际化代理和支持的语言
  • ✅ 部分页面已使用 AppLocalizations.of(context)
  • ❌ 缺少 LocaleService 语言管理服务
  • ❌ 缺少语言设置页面
  • ❌ 缺少 ARB 资源文件（lib/l10n/arb/ 目录为空）
  • ❌ 缺少完整的多语言文本资源

# global 分支参考实现

  • ✅ 完整的 LocaleService 实现
  • ✅ 功能完善的语言设置页面
  • ✅ 完整的 ARB 资源文件（app_en.arb, app_zh.arb）
  • ✅ 2000+ 条多语言文本资源
  • ✅ 支持系统语言、英文、中文三种选项

# 实施计划

# 第一阶段：核心服务和基础设施

# 1.1 创建 LocaleService

文件路径: lib/services/locale_service.dart

功能要求:

  • 管理应用语言设置
  • 支持系统语言、英文、中文三种选项
  • 使用 SharedPreferences 持久化语言偏好
  • 提供 Stream 通知语言变更
  • 与 main.dart 中的语言配置集成

核心方法:

class LocaleService {
  // 获取当前语言
  Future<Locale?> getCurrentLocale()
  
  // 设置新语言
  Future<void> setLocale(String localeCode)
  
  // 获取当前语言代码
  Future<String> getCurrentLocaleCode()
  
  // 语言变更流
  static Stream<Locale?> get localeStream
}

# 1.2 创建语言设置页面

文件路径: lib/pages/settings/language_settings.dart

功能要求:

  • 显示当前选中的语言
  • 提供语言切换选项（系统/英文/中文）
  • 实时切换语言并更新UI
  • 与设置页面集成

# 1.3 更新 main.dart

修改要求:

  • 在应用启动时初始化 LocaleService
  • 监听语言变更流并更新应用语言
  • 确保国际化配置正确

# 技术规范

# 代码规范

# 1. 国际化文本使用 

// ✅ 正确用法
final localizations = AppLocalizations.of(context)!;
Text(localizations.appTitle)

// ❌ 错误用法
Text('OMate')

# 2. 动态文本处理 

// ✅ 使用参数化文本
String welcomeMessage(String name) {
  return 'Welcome, $name!';
}

// ARB 文件中
"welcomeMessage": "Welcome, {name}!",
"@welcomeMessage": {
  "description": "Welcome message with user name",
  "placeholders": {
    "name": {
      "type": "String"
    }
  }
}

# 3. 条件文本处理 

// ✅ 为不同条件提供不同的国际化键
String getStatusText(bool isActive) {
  return isActive ? localizations.active : localizations.inactive;
}

# 质量保证

# 翻译质量标准

  1. 准确性: 翻译内容准确传达原意
  2. 一致性: 同类术语在整个应用中保持一致
  3. 简洁性: 文本简洁明了，符合移动应用特点
  4. 本地化: 考虑目标语言的文化背景和使用习惯

# 测试检查清单

  • 所有页面的文本都已国际化
  • 语言切换功能正常工作
  • 不同语言下UI布局正常
  • 应用重启后语言设置保持
  • 错误提示和警告信息已国际化
  • 时间和日期格式正确本地化
  • 长文本在小屏幕设备上显示正常

# 维护和扩展

# 添加新语言的步骤

  1. 在 lib/l10n/arb/ 目录下创建新的 ARB 文件
  2. 翻译所有文本内容
  3. 在 main.dart 的 supportedLocales 中添加新语言
  4. 在 LocaleService 的 supportedLocales 中添加新语言
  5. 在语言设置页面添加新语言选项
  6. 测试新语言的显示效果

# 添加新文本的步骤

  1. 在所有 ARB 文件中添加新的键值对
  2. 为新键添加描述注释
  3. 运行 flutter gen-l10n 重新生成本地化文件
  4. 在代码中使用新的本地化文本
  5. 测试所有支持语言的显示效果

# 风险和注意事项

# 潜在风险

  1. 文本长度变化: 不同语言的文本长度差异可能影响UI布局
  2. 字体支持: 确保所选字体支持所有目标语言的字符
  3. 文化差异: 某些概念或功能在不同文化中的理解可能不同
  4. 维护成本: 每次添加新功能都需要更新多语言资源

# 解决方案

  1. 在设计UI时预留足够的文本空间
  2. 选择支持多语言的字体系统
  3. 与目标语言的本地用户进行测试和反馈
  4. 建立规范的文本更新流程

# 总结

本规范文档为 OMate gloabal4 分支的国际化实施提供了完整的指导方案。通过分阶段实施，可以确保国际化功能的质量和稳定性。建议在开始实施前，先确认技术方案和资源分配，确保项目顺利进行。

实施完成后，OMate 将能够为不同语言背景的用户提供本地化的使用体验，提升应用的国际竞争力和用户满意度。
