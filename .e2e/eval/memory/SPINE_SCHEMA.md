## 会话骨架（spine）的数据格式

每个会话一个 JSON 文件，UTF-8，顶层字段如下（字段名与类型必须完全一致）：

```json
{
  "id": "s01",
  "title": "夜市摊主与常客",
  "setting": "一句话背景",
  "character": { "name": "沈青", "persona": "一句话人设与说话风格" },
  "user": { "name": "林遥" },
  "greeting": "来啦？今天想聊点什么。",
  "leadIns": ["对了，说说你自己吧。"],
  "facts": [
    {
      "id": "f01",
      "memoryType": "preference",
      "subject": "林遥",
      "relation": "dislikes",
      "object": "香菜",
      "statement": "我这人天生吃不了香菜，闻到就想绕路。",
      "speaker": "user",
      "restatement": null,
      "update": null,
      "probe": "你还记得我看到哪种调味菜就躲着走吗？"
    }
  ],
  "fillerTurns": [ { "user": "……", "assistant": "……" } ],
  "deflections": ["哎，这会儿摊上正忙，等会儿再细说。"],
  "acknowledgements": ["行，这个我记下了。"]
}
```

### 硬性数量
- `facts`：**正好 30 条**。其中带 `update` 的**正好 10 条**；带 `restatement`（非 null）的**至少 8 条**（这 8 条可以和带 update 的重叠）。
- `fillerTurns`：**至少 90 组**。
- `deflections`：**正好 12 条**，彼此不同。
- `acknowledgements`：**正好 16 条**，彼此不同。
- `greeting`：角色的开场白，20 到 60 个汉字，符合人设，不含任何事实内容。
- `leadIns`：**正好 10 条**，彼此不同。用户用来引出角色讲自己的话（5 到 20 个汉字，如「对了，你平时都怎么过？」「说说你家里的事吧。」），**不能包含任何事实的内容**，也不能是探针那种指向具体事实的问题。
- `id`：s01 到 s12；事实 id：f01 到 f30。

### 每条 fact
- `memoryType` 取值之一：`identity`、`preference`、`relationship`、`goal`、`health`、`item`、`location`、`event`、`fact`。
- `subject` / `relation` / `object`：三元组，object 是具体值。`relation` 用简短英文或拼音风格的小写下划线串（如 `allergic_to`、`owns`、`lives_in`）。
- `statement`：一句自然口语，**不超过 40 个汉字**，由 `speaker`（`user` 或 `character`）说出；它会**原样**出现在对话里，所以必须是完整、独立成立的一句话。
- 可变性：`preference`、`relationship`、`goal`、`health`、`item`、`location` 可以有 `update`；`event`、`identity`、`fact` **不可以**（已发生的事和身份不变）。30 条里这三类不可变事实**合计至少 6 条**。
- `update`：为 null 或 `{ "statement": "…", "probe": "…" }`。`statement` 是后来的新状态（原话，不超过 40 个汉字，由同一个人说）；`probe` 是针对**新状态**的探针。
- `restatement`：为 null 或一句换说法重申同一事实的原话（不超过 40 个汉字，同一个人说）。语义必须和 `statement` 完全一致，只是措辞不同——这是「重述负例」，评测用它检验系统不会把重述误判成状态更新。**取值词必须原样保留**：`statement` 里逐字出现的取值词（地名、数量、材质、颜色、时间点等，即 `object` 在原话里的写法）在 `restatement` 里也要出现；不增加原话没有的信息，不丢原话有的限定。
- `probe`：一句向角色提出的问题，由用户说出，**不超过 40 个汉字**。要求：
  1. **换说法**：与对应的 `statement`（以及它的 `restatement`、`update.statement`）**没有任何两个连续汉字相同**——人物名字（`character.name`、`user.name`）除外，常见虚词（的、了、我、你、他、她、它、是、在、有、和、就、都、也、还、吗、呢、啊、吧、这、那、什么、怎么、哪、一个、没有、不、人、说、会、把、被、给、到、过、着、来、去、上、下、里、后、前、时候、现在、之前、以前、记得、知道、告诉）除外。例如事实是「对花生过敏」，探针不能出现「花生」「过敏」，要写成「还记得我吃哪样坚果会出事吗」。
  2. **不泄露答案**：不能把 `object` 或答案的直白同义词写进问题里。
  3. **能从事实回答**：只靠这条事实就能回答。
  4. 不同事实的 `probe` 彼此不同，也不要都长一个样。
  5. **视角**：探针是用户对角色说的话。事实由角色说出（`speaker` 为 `character`）时，事实的主体是「你（角色）」，探针里**不得出现「我」**——否则等于用户认领了角色的事实，而这些句子会原样进入对话与抽取。事实由用户说出时，用「我」指代用户自己，不要反过来问「你的…」。

### fillerTurns（与事实无关的日常对话）
- 每组是一次一来一回：`user` 是用户的话（10 到 40 个汉字），`assistant` 是角色的回应（30 到 90 个汉字，符合人设）。
- **内容必须与所有事实无关**：不能出现任何事实里的信息（人物的偏好、关系、经历、物品、地点、目标、健康状况等），也不能出现探针问的那种问题。写围绕这个会话设定的日常闲聊：天气、生意、琐事、见闻、吐槽、小八卦等。
- 组与组之间内容不要重复。

### deflections 与 acknowledgements
- `deflections`：角色被问到探针时用的、**不带任何信息**的推托话（10 到 30 个汉字，符合人设，不能包含任何事实的内容）。脚本会把它们填在探针之后，避免角色把答案再说一遍污染后续历史。
- `acknowledgements`：角色听到一条事实后的简短回应（6 到 25 个汉字，符合人设，**不能复述事实内容**）。
- `leadIns`（续）：脚本会在角色说出一条事实之前，把其中一条填进用户的话里。

### 质量要求
- 对白要像真实的中文角色扮演对话，自然、有生活气；不要翻译腔，不要套模板。
- 30 条事实要分散在不同话题上，至少覆盖 6 种 `memoryType`；事实之间可以有剧情上的联系，但每条都要能独立核对。
- 带更新的事实：更新后的状态要和原状态**确实不同**（例如「养了一只猫叫团子」→「团子上个月送人了」），不能只是换个说法。10 条更新里，至少 4 条是「关系 / 目标 / 健康状况」这类会随剧情推进而变化的。
- 事实要有可核对的具体值：人名、地名、物品名、数量、日期或时间点、颜色等，避免「喜欢很多东西」这种无法判定的说法。

### 探针「换说法」的机器判定（写手自查与校验脚本用同一套算法）
对一条 fact 的 `probe`，与它的 `statement`、`restatement`（非 null 的）逐一比较；`update.probe` 与 `update.statement` 比较：
1. 两边都去掉 `character.name`、`user.name`（非空时）；
2. 两边都把下面这些「豁免词」当作子串全部删掉：的、了、我、你、他、她、它、是、在、有、和、就、都、也、还、吗、呢、啊、吧、这、那、什么、怎么、哪、一个、没有、不、人、说、会、把、被、给、到、过、着、来、去、上、下、里、后、前、时候、现在、之前、以前、记得、知道、告诉；
3. 去掉所有标点、空格、数字以外的非汉字字符；数字按字面保留；
4. 取事实一边全部「连续两个字符」的集合，探针一边同理；**两个集合不得有交集**。有交集即违规，必须改写探针。

### 另外两条机器校验（语义上最容易写错、又直接影响指标的两处）
- **探针视角**：`speaker` 为 `character` 的事实，`probe` 与 `update.probe` 里不得出现「我」。
- **重述保住取值词**：`object`（或其中任一长度 ≥ 2 的连续词段）逐字出现在 `statement` 里时，它也必须出现在 `restatement` 里。

这两条是 12 个骨架写完后做人工语义审计时补上的：当时有 57 处探针视角写反（集中在角色说出的事实上），另有若干重述丢了取值词。
